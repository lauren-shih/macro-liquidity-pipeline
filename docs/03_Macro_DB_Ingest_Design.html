0. Why this design exists

The quant_research warehouse already holds 7 ingested TEJ equity tables (tej_* prefix). This design lands the 40-indicator macro pipeline output in the same DB under a macro_* prefix, so that:

  • multi-factor / Fama-MacBeth work pulls LHS (TEJ equity returns) + RHS (macro factors) with a single SQL JOIN;
  • YoY / bps differences / level changes can be inspected directly in any SQL client;
  • the selection-side LHS table (tej_universe_returns_monthly) lives beside the macro panel — built by a separate TEJ flow (planned — §2.2, §4.3), for the factor-selection side to pull via plain SQL.

Architectural principle: the parquet stays the SSoT; the DB is a downstream consumer — the macro pipeline remains standalone-testable, and no production code is modified by this layer.

Key invariant: macro_panel_features.parquet is the production SSoT. If the DB ingest fails, the DB schema changes, or the DB moves — the macro pipeline is unaffected.

Scope boundary: the ingest notebook produces only macro_panel + macro_panel_indicators (macro domain). tej_universe_returns_monthly (equity-domain LHS) belongs to a separate TEJ flow: it is aggregated from the already-ingested tej_* raw tables in a first equity-side step (planned) and written back to the same DB, so selection and Fama-MacBeth can share one persisted LHS table (data consistency + DRY). The two domains meet only at SQL-JOIN time. Status today: the raw per-stock tej_* tables are in the DB; this monthly aggregate table — and the macro tables — are not yet built, so the SQL-JOIN path is design-stage end-to-end.

2. Schema design

2.1 Main table macro_panel (long-format)

CREATE TABLE IF NOT EXISTS macro_panel (
    series_id     TEXT    NOT NULL,    -- e.g. 'SOFR', 'BAMLH0A0HYM2', 'TFF_10Y_LEVERAGED'
    date          DATE    NOT NULL,    -- data_date (reference period end / observation date)
    transform     TEXT    NOT NULL,    -- 'level' | 'diff' | 'diff_bps' | 'pct1m' | 'yoy'
    value         REAL,                -- transformed value (NaN allowed for early sample)
    release_date  DATE,                -- effective release date (when public knew this value)
    block         TEXT,                -- 1-9 (rates / liquidity / credit / curve / vol / leverage / fx / macro / cftc)
    -- housekeeping columns (aligned with the tej_* table convention)
    fetched_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    source        TEXT      DEFAULT 'macro_pipeline',
    PRIMARY KEY (series_id, date, transform)
)

Design rationale:

  • Long-format: a new indicator is an INSERT, not an ALTER TABLE; a new transform needs no schema change.
  • PRIMARY KEY (series_id, date, transform): idempotent INSERT OR IGNORE dedup.
  • date is the data date, not the release date — aligned with the pipeline's panel index convention.
  • release_date as an explicit column is the PIT-integrity core: downstream SQL JOINs use it as the as-of guard.
  • block: metadata for SQL filtering (e.g. WHERE block IN ('3','6') pulls the credit + leverage subset).

2.2 LHS aggregation table tej_universe_returns_monthly (separate TEJ flow, not this ingest)

⚠️ Scope note: this table is not produced by collect_macro_data.ipynb. It belongs to the equity domain — aggregated from the already-ingested tej_* raw tables in a first equity-side step (planned), then written back to the DB. It is documented here because it co-habits with macro_panel and the two meet at JOIN time, so schema consistency belongs in one place. The published factor-selection run computed this same equal-weight aggregate in-notebook; this table is the planned persisted home of that aggregation.

CREATE TABLE IF NOT EXISTS tej_universe_returns_monthly (
    year_month             TEXT    NOT NULL,    -- 'YYYY-MM' format
    universe_label         TEXT    NOT NULL,    -- 'equal_weight' | 'cap_weight'
    n_stocks               INTEGER,             -- universe size that month
    monthly_return         REAL,                -- aggregate monthly return
    -- housekeeping columns
    fetched_at             TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    source                 TEXT      DEFAULT 'tej_universe_aggregation',
    PRIMARY KEY (year_month, universe_label)
)

Why aggregate-and-persist: the aggregation logic runs on the equity side, but the result is persisted to a DB table rather than kept in memory. Reasons: (1) DRY + consistency — selection and Fama-MacBeth read the same persisted LHS, so small logic drifts (month-end alignment; whether a within-month IPO enters equal-weight) cannot silently diverge; (2) SQL-client inspectability — universe monthly returns can be quality-checked with a plain query; (3) compute once — when the table exists, the selection side simply SELECTs both LHS variants (equal-weight primary + cap-weight robustness — same universe, weighting isolated) instead of re-aggregating 2,049 stocks (PIT universe, delisted included).

2.3 Metadata table macro_panel_indicators (static lookup)

CREATE TABLE IF NOT EXISTS macro_panel_indicators (
    series_id          TEXT    PRIMARY KEY,
    full_name          TEXT,                -- 'Secured Overnight Financing Rate'
    fred_id            TEXT,                -- 'SOFR' (FRED) / 'TFF_10Y_LEVERAGED' (CFTC)
    block              TEXT    NOT NULL,    -- 1-9
    block_name         TEXT,                -- 'Repo Plumbing' / 'Liquidity' / ...
    category           TEXT,                -- statistical tag (rates / liquidity / leverage / ...)
    publication_lag    INTEGER,             -- standard-path config value (days)
    pit_path           TEXT,                -- 'standard_fixed_lag' | 'alfred_vintage'
    real_lag_days      INTEGER,             -- empirical (e.g. CPI 42, M2 55, PCEPILFE 58)
    tier               INTEGER,             -- 1 (deep) / 2 (mid) / 3 (light)
    is_working         INTEGER DEFAULT 1,   -- 1 if functional, 0 if the upstream id is retired
    fetched_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    source             TEXT      DEFAULT 'macro_pipeline'
)

Why: any query can JOIN macro_panel m ON m.series_id = i.series_id and read block / pit_path / lag metadata directly, instead of memorising per-series facts.

3. release_date logic (3 source groups)

Every computed release date is verified against the official release schedule rather than assumed.

Implementation: fred_loader_vintage.py already exposes the realtime_start column; the ingest reads it straight into macro_panel.release_date (§5).

Source Group 3: CFTC TFF (2 series) — verified ground truth

ItemVerified value (CFTC.gov + secondary sources)
Data dateTuesday (weekly open-interest as-of date)
Release dateFriday 3:30 PM Eastern Time (weekly)
Lag (regular)3 business days (Tue → Fri)
Holiday ruleMonday US federal holiday → data shifts Tue → Wed; Friday holiday → release shifts to Thursday

Implementation:

import pandas as pd
from pandas.tseries.holiday import USFederalHolidayCalendar
from pandas.tseries.offsets import CustomBusinessDay

us_bday = CustomBusinessDay(calendar=USFederalHolidayCalendar())

def cftc_tff_release_date(data_date_tuesday):
    """
    Calculate CFTC TFF release date.
    Standard: Tuesday data → Friday release (3 business days).
    Federal holiday on Friday shifts release to Thursday;
    Federal holiday on Monday shifts data collection to Wednesday (data_date already shifted upstream).
    """
    # data_date is already Tuesday (it arrives already shifted in the CFTC/Socrata feed; cftc_loader passes report_date through unchanged)
    # Standard: + 3 business days (Tue + 3 BDay = Fri)
    release = data_date_tuesday + 3 * us_bday
    return release

4. Ingest function design

4.1 Main function

Values for all series — vintage included — come from the features parquet (single value source); this function melts the wide panel to long-format and attaches release_date per source group.

def ingest_macro_panel(
    parquet_path: Path,          # output/macro_panel_features.parquet
    conn: sqlite3.Connection,
    config_module,                # imported config.py for Indicator metadata
) -> dict:
    """
    Read macro_panel_features.parquet (wide-format),
    melt to long-format,
    compute release_date per source group,
    INSERT OR IGNORE into macro_panel.

    Returns: dict with rows_read / rows_inserted / rows_skipped (idempotent dedup) / errors
    """
    # Step 1: Read parquet (wide-format)
    df_wide = pd.read_parquet(parquet_path)
    # df_wide.index = DateTimeIndex (business days)
    # df_wide.columns = [SOFR, BAMLH0A0HYM2, BAMLH0A0HYM2_diff_bps, ..., DEXTAUS_pct1m, ...]

    # Step 2: Melt to long-format
    df_long = df_wide.reset_index().melt(
        id_vars=['date'],
        var_name='series_transform',
        value_name='value'
    )

    # Step 3: Parse series_id + transform from column name
    # e.g. 'SOFR' → ('SOFR', 'level')
    # e.g. 'DEXTAUS_pct1m' → ('DEXTAUS', 'pct1m')
    # e.g. 'BAMLH0A0HYM2_diff_bps' → ('BAMLH0A0HYM2', 'diff_bps')
    df_long[['series_id', 'transform']] = df_long['series_transform'].apply(
        parse_series_transform
    )

    # Step 4: Compute release_date per source group
    df_long['release_date'] = df_long.apply(
        lambda row: compute_release_date(
            row['series_id'], row['date'], config_module
        ),
        axis=1
    )

    # Step 5: Add block metadata
    df_long['block'] = df_long['series_id'].apply(
        lambda sid: get_block_from_config(sid, config_module)
    )

    # Step 6: INSERT OR IGNORE (idempotent)
    df_long_clean = df_long.dropna(subset=['value'])  # skip NaN rows
    cur = conn.cursor()
    cur.executemany("""
        INSERT OR IGNORE INTO macro_panel
        (series_id, date, transform, value, release_date, block)
        VALUES (?, ?, ?, ?, ?, ?)
    """, df_long_clean[['series_id', 'date', 'transform', 'value', 'release_date', 'block']].values.tolist())
    rows_inserted = cur.rowcount
    conn.commit()

    return {
        'rows_read': len(df_long),
        'rows_inserted': rows_inserted,
        'rows_skipped_nan': len(df_long) - len(df_long_clean),
        'rows_skipped_dup': len(df_long_clean) - rows_inserted,
    }

4.2 release_date dispatcher

def compute_release_date(series_id, data_date, config_module):
    """
    Dispatch to one of 3 source groups for release_date.
    """
    # Group 1: ALFRED VINTAGE_SERIES
    if series_id in config_module.VINTAGE_SERIES:
        # release_date = true first-release date, looked up from cache_vintage — see §5
        return get_alfred_realtime_start(series_id, data_date)

    # Group 3: CFTC TFF
    if series_id.startswith('TFF_'):
        return cftc_tff_release_date(data_date)

    # Group 2: FRED standard fixed-lag (default)
    indicator = config_module.get(series_id)
    return data_date + pd.Timedelta(days=indicator.lag)  # dataclass field: lag (the DB column publication_lag maps from it)

4.3 LHS aggregation (planned equity-side step — not this ingest)

⚠️ Scope note: this function does not belong to collect_macro_data.ipynb. It runs as a first equity-side step (planned) and writes its result back to the DB. It is documented here because the schema co-habits with macro_panel; selection and Fama-MacBeth share the persisted table.

def build_tej_universe_returns_monthly(conn):
    """
    Pre-aggregate TEJ universe returns at month-end, 2 universe labels.
    Idempotent via INSERT OR IGNORE.
    ⚠️ Planned equity-side step (not part of the collect_macro_data ingest).
    """
    # 1. Equal-weight TEJ universe (selection primary LHS)
    eq_weight_sql = """
    WITH daily_returns AS (
      SELECT 
        t.coid,
        t.mdate,
        strftime('%Y-%m', t.mdate) AS year_month,
        t.roia / 100.0 AS daily_ret
      FROM tej_ewprcd2 t
      WHERE t.mdate BETWEEN :win_start AND :win_end   -- research-window guard (mirror the estimation window)
      -- ⚠️ PIT universe (survivorship-corrected): do NOT JOIN tej_ewnprcstd to apply a
      --    snapshot filter (n.market IN ('TSE','OTC')) — that would re-exclude the
      --    backfilled delisted stocks (market='DIST'), silently re-introducing
      --    survivorship bias into the LHS / market factor. The members of tej_ewprcd2
      --    (distinct coid within the research window = 2,049) ARE the PIT-universe SSoT; delisted stocks contribute
      --    returns only in their traded months and drop out afterwards — exactly the
      --    PIT behaviour we want. The
      --    universe-construction layer owns include/exclude decisions; not redefined in this query.
    ),
    monthly_per_stock AS (
      SELECT 
        coid, year_month,
        EXP(SUM(LN(1.0 + daily_ret))) - 1.0 AS monthly_ret
      FROM daily_returns
      GROUP BY coid, year_month
    )
    INSERT OR IGNORE INTO tej_universe_returns_monthly
    (year_month, universe_label, n_stocks, monthly_return)
    SELECT 
      year_month, 'equal_weight', COUNT(*), AVG(monthly_ret)
    FROM monthly_per_stock
    GROUP BY year_month
    """

    # 2. Cap-weight TEJ universe (robustness; also the FM market-factor source)
    #    Same PIT principle: no snapshot filter; cap weights from PIT data; delisted stocks count in their traded months.

    conn.execute(eq_weight_sql)
    # ... execute the cap-weight variant
    conn.commit()

5. Vintage release_date lookup

For the 8 VINTAGE_SERIES, release_date cannot be computed as data_date + lag — the true first-release date is ALFRED's realtime_start, already persisted in src/cache_vintage/*.parquet (long-format: realtime_start, date, value).

This path supplies release dates only. The values themselves are read from the features parquet like every other series (single value source; the pipeline computes vintage transforms uniformly via apply_transforms(mode='fm')). The notebook implements this as a split, not an overwrite: Cell 5 melts the full features parquet but inserts only the standard + CFTC rows; Cell 6 takes the vintage rows set aside by that melt, attaches release_date by a backward as-of join on the cached first-release dates (grid dates before a series' first vintage are dropped, not ingested), and inserts them — values from the features parquet throughout; the end state matches the §4.2 dispatch.

def vintage_release_date_map(config_module) -> dict:
    """
    Build {series_id: {data_date: release_date}} for the 8 VINTAGE_SERIES.
    release_date = min realtime_start per data_date (first release) —
    explicit stable sort + drop_duplicates, mirroring pit_safe_vintage.extract_first_release.
    """
    VINTAGE_CACHE_DIR = Path("src/cache_vintage")   # note: the path constant lives in the vintage loader, not config
    out = {}
    for series_id in config_module.VINTAGE_SERIES:
        df = pd.read_parquet(VINTAGE_CACHE_DIR / f"{series_id}.parquet")
        first = (df.sort_values(['date', 'realtime_start'], kind='stable')
                   .drop_duplicates(subset=['date'], keep='first'))
        out[series_id] = dict(zip(first['date'], first['realtime_start']))
    return out

7. Verification queries

-- Q1: row count per transform
SELECT transform, COUNT(*) AS n
FROM macro_panel
GROUP BY transform;

-- Q2: series count + row count per block
SELECT block, COUNT(DISTINCT series_id) AS n_series, COUNT(*) AS n_rows
FROM macro_panel
GROUP BY block;

-- Q3: release_date vs data_date gap distribution per series
SELECT 
    series_id, 
    transform,
    AVG(julianday(release_date) - julianday(date)) AS avg_lag_days,
    MAX(julianday(release_date) - julianday(date)) AS max_lag_days,
    MIN(julianday(release_date) - julianday(date)) AS min_lag_days
FROM macro_panel
WHERE transform = 'level'
GROUP BY series_id;

-- Q4: ALFRED VINTAGE_SERIES vs standard fixed-lag comparison
SELECT 
    m.series_id,
    i.pit_path,
    i.publication_lag AS config_lag,
    AVG(julianday(m.release_date) - julianday(m.date)) AS empirical_lag,
    AVG(julianday(m.release_date) - julianday(m.date)) - i.publication_lag AS lag_gap
FROM macro_panel m
JOIN macro_panel_indicators i ON m.series_id = i.series_id
WHERE m.transform = 'level'
GROUP BY m.series_id, i.pit_path, i.publication_lag;
-- Expected: VINTAGE_SERIES empirical_lag ≈ CPI 42 / M2 55 / PCEPILFE 58; publication_lag is NULL for vintage rows → lag_gap undefined
-- standard fixed-lag series: gap ≈ 0 (calibrated per the ALFRED sweep)

-- Q5: Sample as-of join (RHS macro + LHS equity, no look-ahead)
SELECT 
    u.year_month,
    u.universe_label,
    u.monthly_return AS lhs_return,
    m.value AS rhs_hy_oas_dbps
FROM tej_universe_returns_monthly u
LEFT JOIN macro_panel m
    ON m.series_id = 'BAMLH0A0HYM2'
    AND m.transform = 'diff_bps'
    AND m.release_date <= date(u.year_month || '-01')  -- as-of guard
WHERE u.universe_label = 'equal_weight'
ORDER BY u.year_month
LIMIT 10;

8. Limitations & design boundaries

  • Standard-path publication_lag values are calibrated config defaults, not per-release actuals (the ALFRED sweep confirmed a median real lag of 0–1 day for rates, credit and balance-sheet series; the two FX series read ≈5 days against the weekly H.10 archive — DEXTAUS stays at config lag 1 by design, DTWEXEMEGS is calibrated at 5 (Integration §6); monthly macro takes the first-release route instead).
  • CFTC TFF holiday shifting uses the standard USFederalHolidayCalendar, not NYSE-specific holidays (difference minimal at weekly cadence).
  • FINRA margin debt (monthly) follows the same standard fixed-lag rule through the dispatcher's default branch (lag=25); as a non-FRED source it is not ALFRED-sweep-verifiable — its lag is calibrated from the FINRA release schedule.
  • The DB is refreshed only when the ingest notebook is re-run; it is a research warehouse, not a live mirror of the parquet.
